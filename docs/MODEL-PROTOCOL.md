# 映流 Studio 对话模型协议

当前应用有两个明确的模式。默认 `demo / offline-director` 是本地确定性演示，不调用远程 API；它按主题生成三段提纲、配色和可编辑 HTML/CSS/JS，执行本地代码预览。`custom` 才会使用用户在当前应用中配置的兼容模型接口。真实模型创作在本次开发验收中保持 `NOT_CHECKED`。

## 接入自定义模型

在模型设置填写服务地址、模型 ID 和 API Key，切换自定义模式。默认地址为 `https://api.deepseek.com/v1`，默认模型为 `deepseek-chat`；不会默认选择 OpenAI，也不会读取 DSH、Codex 或其它应用的凭据。配置的 `/chat/completions` 应支持 `messages`、`max_tokens`、文本回复及 SSE 或普通 JSON 完成回执。图片能力字段目前仅是保存的配置，应用这条导演路径仍只发送图片/素材文字元信息。

ProviderManager 把非敏感配置写入应用数据目录的 `provider.json`；API Key 只交给注入的 `SecretStore`。UI 得到 `hasKey`，不会收到 Key。聊天记录按工程 ID 的 SHA256 文件名写入 `conversations/`。本机 SecretStore 的具体持久化与加密保证由桌面宿主实现，不由这份模型协议推断。

“检查连接”是显式 `GET /models`，用于确认服务和目录可访问；它不执行创作，也不能证明指定模型完成了视频代码生成。没有配置当前应用自己的 Key 时，创作请求会报错。实现与测试未使用真实付费模型。

## 同一多轮对话的导演循环

每轮读取当前工程、稳定镜头 ID、节点主链顺序、选中镜头、素材元信息和 revision，再把最近 16 条对话与当前制作上下文送给同一个模型。模型返回 JSON 导演计划，应用执行允许的动作，将实际回执追加到本轮上下文。最多 3 轮，每轮最多 8 个动作、7,000 个输出 token，单次接口请求上限 90 秒，整个对话任务上限 240 秒。取消会中止模型请求，并仅取消本轮拥有的本地检查任务。

计划示例：

```json
{
  "message": "第二个镜头改为滑入，保留手动标题",
  "done": true,
  "actions": [{
    "tool": "video_update",
    "arguments": {
      "expectedRevision": 5,
      "update": {
        "shotPatches": [{"id": "existing-shot-id", "patch": {"params": {"motion": "slide"}}}]
      }
    }
  }]
}
```

五类动作复用视频工具语义，当前独立 demo 有具体限制：

| 动作 | 当前支持 |
|---|---|
| `video_project` | 读取当前工程；工程首次创建由应用协调器完成 |
| `video_update` | 初稿的 `storyboard.shots` 与对应 `sourcesByIndex`；已有工程的镜头局部参数/源码修改 |
| `video_inspect` | 工程、分镜要求、可选镜头源码的元数据回读；不向模型发送 PNG |
| `video_render` | 本地预览和运行检查；MP4 导出由界面按钮明确触发 |
| `video_audio` | 编辑已导入音轨的绑定、参数和删除；模型不能自行远程合成或读取任意本地音频文件 |

初稿要求 3–5 镜，每镜提供源码，应用分配 ID 并归一化整数帧时长。现有工程不接受模型全量覆盖镜头或重排主链；默认只允许选中、语句明确指定或明确要求全片的镜头。每次提交必须附带 `expectedRevision`，由后端最终提交边界检查。中文“第二镜”“第三个镜头”等按当前主链顺序定位，用户的手动标题在没有明确改名请求时保留。

## 源码与检查回执

场景源码由 `html`、`css`、`js` 构成，JS 导出 `render(ctx)`，可导出异步 `ready(ctx)`。画面按 `frame/localFrame/time` 求值，文本、配色、运动等读取 `ctx.params`，不依赖墙钟或自主播放。模型提示里的“不联网、不安装”仅是生成约束；代码的实际权限由渲染服务和桌面隔离实现负责。

初稿落盘后应用执行预览、关键帧代码运行检查，并回读工程/镜头元数据。成功回执仅代表这些步骤完成，不能扩展为模型视觉检查、人工观看、跨设备像素一致或真实供应商创作验收。PNG 像素没有送给当前导演模型，所以 UI 与记录不得声称模型看过图像。

内置工作包中的六种设计配方作为导演参考传入提示，全部标记 `design_proposal`；复制配方、显示目录或让模型参考配方都不代表六个风格渲染器已经实现。离线三段演示场景与这些设计提案分别记录。
