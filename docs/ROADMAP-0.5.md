# 映流 0.5 改进方案：结构化创作计划与一致性

> 依据：0.4.0 冻结版（标签 `v0.4.0`）的智能体审计，以及同赛道开源项目调研（ViMax、wind-comic、kineo/Novella、ai-comic-studio、MoneyPrinterTurbo、NarratoAI、Remotion/skills、Manim/TheoremExplainAgent、ComfyUI 等）。只借鉴思路，不复制任何代码或文档；Remotion 与无许可证仓库的内容一律不引入。

## 目标
1. 导演先出「可审阅的计划」再动手：剧本、风格设定、角色和分镜成为结构化、可持久化的工程数据（`story.json`），而不是临时推理。
2. 角色和风格在多镜头之间保持一致，并且一致性可以量化、可以追溯。
3. 成本按项目累计、可以设上限；导出前自动质检，拦住明显的废片。
4. 导演自制画面的质量更稳定（自写的技能文档），镜头之间衔接更顺（尾帧承接、配音对齐）。

## 范围与设计

### P0-1 结构化计划 `story.json` + 计划审批
- 数据：`{ title, logline, targetSeconds, style{look,palette,typography,motion,negative}, characters[], shots[], status, approvedAt, consistency{} }`。按工程保存在智能体数据目录 `stories/<projectId>.json`，原子写入，带版本号（`version`）防止覆盖他人修改。
- 新风险级别 `plan`：默认**需要人批准**，可以在启动时设为自动批准。
- 工具：`story_get`（读）、`plan_story`（plan：剧本、风格、角色）、`plan_shots`（plan：分镜表，含景别、运镜、时长、台词、出场角色、是否承接上一镜）。审批卡片用结构化视图展示计划内容。
- 系统提示：工程没有已批准的计划时，复杂目标先 `plan_story` → `plan_shots`，批准后再改镜头；批准后的计划自动注入上下文。

### P0-2 角色库与一致性
- 角色：`{ id, name, description, features[]（发型、脸型、服装、配色等可见特征）, referenceAssetIds[], voice? }`。用户可以在「角色库」里编辑并挑选参考图；智能体用 `character_upsert`（write，可撤销语义＝覆盖保存）维护。
- 注入：`generate_image` / `generate_video` 新增 `characterIds` 参数，提示词自动拼接风格设定和角色特征锚点；`generate_video` 在没有给首帧时，可以用角色的第一张参考图作为参考（只在设置了 `useReference` 时）。
- 打分：`consistency_review`（需要 vision 角色）按镜头截取关键帧，连同角色特征让视觉模型打 0–100 分，结果写入 `story.consistency`。低于阈值（默认 75）的镜头返回「建议重生」；真正重生仍然走收费工具，**每次都需要批准**，不会自动花钱。

### P1-1 项目级预算与导出前质检
- 项目账本 `ledger/<projectId>.json`：累计花费、未知费用调用次数、按工具分项，可以设置项目费用上限（`maxCost`）。收费工具预计会超过项目上限时强制审批；花费已达上限时运行停止。
- 质检 `quality_check`（读）与端点 `agent.qc`：
  - 黑帧/空白：按镜头截取中间帧，对 PNG 解码并计算平均亮度和方差（无法解码的格式标记为「未检查」）。
  - 静音：音频模式为混音但没有任何音轨；计划中有台词的镜头既没有配音也没有字幕；音量为 0 的片段。
  - 字幕越界：按画幅宽度和字号估算每行容量，超过两行或配音片段超出镜头时长。
  - 时长：总时长与计划/目标时长相差超过 20%；镜头短于 0.5 秒。
- `export_mp4` 先跑质检；有严重问题时拒绝导出，并给出问题列表（参数 `force: true` 可强制导出，仍然需要导出审批）。

### P1-2 导演技能文档（自写）
- `src/agent/skills.ts`：按主题组织的简短指南（镜头源码结构、确定性动画与帧对齐、版式与安全区、字幕、性能、常见错误），用 `skill_read`（读）按需加载，避免一次塞满上下文。全部自写，不复制 Remotion 等外部文档。

### P1-3 尾帧承接与配音对齐
- `frame_handoff`（write）：截取上一镜最后一帧，导入为图片素材，返回素材 ID，供 `generate_video` 作为首帧（图生视频），保证镜头之间衔接。
- `align_to_voice`（write）：根据配音素材时长，自动把镜头时长调整为「配音时长 + 余量」，并把配音片段对齐到镜头开头；一次提交，可撤销。

## 验收标准
- 新工具都有单元测试或集成测试，**只用模拟网关**；`npm run typecheck`、`npm run build`、`npm test` 全部通过。
- 计划工具默认触发审批；拒绝后计划不落盘。
- 生成提示词中包含风格和角色锚点（测试断言网关收到的提示词）。
- 一致性低分只给出重生建议，不会自动调用收费工具。
- 项目上限：超过上限的收费调用必须审批，花费累计跨运行保留。
- 质检能识别全黑帧、缺少音轨、字幕过长、时长偏差；有严重问题时导出被拦截。
- UI：智能体面板可以查看和审批计划（结构化视图）、编辑角色库、查看一致性分数、运行质检、设置项目预算。

## 不做（留到 0.6+）及理由
- **子智能体/共享黑板并行**：先用结构化计划把单导演的稳定性做上去；`story.json` 本身就是将来的黑板，多智能体可以在此基础上演进。
- **ComfyUI 后端**：需要工作流 JSON 协议和本地 GPU 环境，实测成本高；现有模板协议可以经网关接入。
- **模板市场、口型同步**：依赖真实生成链路的验收和素材版权策略，暂不做。
- **视觉参考图直接喂给生图模型（图生图）**：各服务参数差异大，0.5 只做文字锚点和视频首帧参考。
- **音频波形级静音检测**：需要 FFmpeg 解码；0.5 先做工程数据层面的检查。
